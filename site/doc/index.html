电力遥测 API

让 ESP8266-12F、ESPHome 节点或 BLE 网关把 DDSU666 的 DL/T 645-2007 原始帧安全写入监控服务，业务解析留在服务器。

POST https://iot.ohmyskills.top/api/v1/dlt645/frame https://iot.ohmyskills.top/api/v1/dlt645/frame
端口关系
浏览器文档https://iot.ohmyskills.top/doc公网 443 · 静态文档
域名 APIhttps://iot.ohmyskills.top公网 443 · 受信任证书
裸 IP 调试http://<PUBLIC_IP>受控网络 · 不用于生产

部署提示：域名和裸 IP 节点运行同一套原始帧服务。域名请求走标准 443；裸 IP 仅用于 VPN/LAN 或临时联调。Arduino 1.6.8 兼容固件当前使用 TLS 加密但跳过服务器身份校验，以避免证书续期后重新烧录。

02

上报接口

POST/api/v1/dlt645/frame需要鉴权

设备将一个测量点的 1 条或多条 DL/T 645-2007 原始帧提交到 API。服务器只记录原文并返回 202 Accepted。

请求头

Headers
名称值说明
AuthorizationBearer <DEVICE_TOKEN>设备独立令牌，不要写入网页或公开仓库。
Content-Typeapplication/json请求体必须是 UTF-8 JSON。

请求体

JSON
{
  "site_id": "home-pv",
  "device_id": "esp8266-12f-001",
  "measurement_point_id": "inverter-ac-output",
  "protocol": "DL/T 645-2007",
  "frames": [
    {
      "sequence": 1042,
      "captured_at": "2026-08-16T04:01:05+08:00",
      "direction": "rx",
      "frame_hex": "68010203040568910433333333333316"

  ]
}

字段约束

Payload
字段类型必填规则
site_idstring是1～64 个字母、数字、.、_、:、-。
device_idstring是设备身份，建议烧录板号，例如 esp8266-12f-001。
measurement_point_idstring是测量点身份，例如 inverter-ac-output。
protocolstring是固定为 DL/T 645-2007。
framesarray是每批 1～100 帧；请求体最大 256 KiB。
sequenceinteger是0～2^63-1；同一设备和测量点单调递增。
captured_atRFC 3339是必须带时区，例如 +08:00 或 Z。
directionstring否tx 或 rx，默认 rx。
frame_hexstring是偶数长度十六进制原文；服务端不解析帧内容。
04

ESP8266-12F 请求示例

下面示例使用 Arduino ESP8266 Core 3.x 的 ESP8266HTTPClient。它演示联网、TLS 请求、Bearer Token 和原始帧上报；frameHex 应替换为 RS485 UART 收到的完整 DL/T 645-2007 字节序列。

Arduino C++ · ESP8266-12F
#include <Arduino.h>
#include <ESP8266WiFi.h>
#include <ESP8266HTTPClient.h>
#include <WiFiClientSecureBearSSL.h>

const char* WIFI_SSID = "YOUR_WIFI_SSID";
const char* WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";
const char* DEVICE_TOKEN = "YOUR_DEVICE_TOKEN";
const char* API_URL = "https://iot.ohmyskills.top/api/v1/dlt645/frame";

BearSSL::WiFiClientSecure tlsClient;
uint64_t sequenceNumber = 1042;

void connectWifi() {
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
  }
}

bool postRawFrame(const String& frameHex, const char* direction) {
  HTTPClient http;
  if (!http.begin(tlsClient, API_URL)) {
    return false;
  }
  http.setTimeout(10000);

  http.addHeader("Authorization", String("Bearer ") + DEVICE_TOKEN);
  http.addHeader("Content-Type", "application/json");

  const uint64_t sequence = sequenceNumber;
  String payload = "{\"site_id\":\"home-pv\",\"device_id\":\"esp8266-12f-001\",";
  payload += "\"measurement_point_id\":\"inverter-ac-output\",";
  payload += "\"protocol\":\"DL/T 645-2007\",\"frames\":[{";
  payload += "\"sequence\":" + String(sequence) + ",";
  payload += "\"captured_at\":\"2026-08-16T04:01:05+08:00\",";
  payload += "\"direction\":\"" + String(direction) + "\",";
  payload += "\"frame_hex\":\"" + frameHex + "\"}]}";

  int status = http.POST(payload);
  String response = http.getString();
  http.end();

  Serial.printf("HTTP %d\n%s\n", status, response.c_str());
  if (status != 202) return false;
  sequenceNumber++;
  return true;
}

void setup() {
  Serial.begin(115200);
  connectWifi();

  // 仅用于无 CA 配置的桌面联调，不校验证书身份。
  // 生产环境应删除下一行，并加载域名 CA 后调用 setTrustAnchors(&cert)。
  tlsClient.setInsecure();
}

void loop() {
  if (WiFi.status() != WL_CONNECTED) {
    connectWifi();
  }

  String frameHex = "68010203040568910433333333333316";
  postRawFrame(frameHex, "rx");
  delay(5000);
}
采集边界：示例中的 frameHex 只是占位原文。正式固件应从 UART 缓冲区复制完整帧并转成十六进制；不要在 ESP8266 上计算数据标识、加 0x33、校验 CS 或换算功率。时间戳应通过 NTP 校时。

2. 填写通用配置

Required

打开程序顶部的配置区，替换 Wi-Fi 和设备 Token。每台设备应使用独立、可吊销且仅允许写入本设备数据的 Token。

旧版固件入口：使用私有部署配置中的兼容 API 地址和端口。程序不经过域名、Cloudflare 或标准 HTTPS 入口；烧录前填写 Wi-Fi、设备 Token 和私有 API endpoint。

3. 先发送模拟报文

API Test

第一次烧录可以直接下载“API 模拟程序”：它不初始化 RS485，启动后只发送一次固定报文并打印完整 HTTP 响应。也可以在完整程序里把开关改成 true，此时程序每 5 秒调用 sendSimulatedFrame()，不访问电表。

模拟模式
const bool SEND_SIMULATED_FRAME = true;
模拟模式仍需要：正确的 Wi-Fi 和 Token；但不需要证书指纹、电表地址或 RS485 连接。日志出现 HTTP status: 202 和 Uploaded simulated frame，表示上报链路正常。
日志串口：完整程序固定由 UART0/Serial 连接 RS485，日志固定从 UART1/Serial1 的 TX（GPIO2）输出。USB-TTL 的 RX 接 GPIO2、GND 接 GND，使用 115200/8N1，TX 线不要连接；SEND_SIMULATED_FRAME 只控制是否跳过电表查询。

4. 切换到真实电表

DDSU666

模拟测试成功后，把开关恢复为 false，按电表铭牌或通信手册填写六字节地址，并确认电压、电流和瞬时总有功功率的数据标识。地址在 DL/T 645 线路中采用低字节在前的顺序。

真实电表模式
const bool SEND_SIMULATED_FRAME = false;

const uint8_t METER_ADDRESS[6] = {
  0x00, 0x00, 0x00, 0x00, 0x00, 0x00  // 按现场电表地址替换
};
const bool METER_ADDRESS_IS_CONFIGURED = true;

// 程序内置三项查询：A 相电压、A 相电流、瞬时总有功功率。
A 相电流示例
请求: 68 [6 字节电表地址] 68 11 04 33 34 35 35 [CS] 16
响应: 68 [6 字节电表地址] 68 91 07 33 34 35 35 33 33 33 [CS] 16
结果: 电压、电流、功率均由服务端解析
数据流说明：程序依次查询 A 相电压、A 相电流和瞬时总有功功率，分别生成对应的 DL/T 645 请求并上传原始响应。0x02030000 即当前瞬时总有功功率查询，不再重复发送相同指令。ESP8266 只负责请求、接收和上传完整响应原文，不在本地换算数值。
排查日志：每次查询都会从日志口打印请求帧和请求校验和；收到响应后打印响应字节数和响应校验字节。例如 RS485 request: ... CS=0x0F。三个指标之间固定等待 1 秒，给电表留出收发切换时间。现场联调已确认：此前 300 ms 间隔会导致响应截断或错位，改为 1 秒后读取稳定，不要随意调小。无响应时不上传；收到 FE、半帧或校验错误时，会原样上传到带 :invalid-response 后缀的测量点，便于监控串口状态。真实电表模式请从 GPIO2 的 TX-only 日志口查看。
方法作用是否解析功率
readHttpResponse()读取 HTTP 状态码和响应正文，不解析业务 JSON。否
uploadRawFrame()统一组装 JSON、添加 Bearer Token、建立 TLS 连接并 POST 原始帧。否
pollMeter()切换 RS485 收发方向，发送一次查询并取得回复。否
readMeterResponse()等待并保存 UART 收到的电表原始字节。否
bytesToHex()把二进制字节转换成 JSON 可携带的十六进制文本。否
sendSimulatedFrame()跳过电表，直接上传固定测试帧。否

5. 编译与烧录

Upload
  1. 先点击 Arduino IDE 左上角的“验证”按钮，确认编译完成。
  2. ESP8266-12F 进入烧录模式：GPIO0 接地后重新上电或复位。
  3. 选择 USB-TTL 对应的串口，点击“上传”；上传完成后断开 GPIO0 与地，再次复位运行。
  4. 烧录结束后断开 USB-TTL 的 TX/RX。UART0 的 GPIO1/GPIO3 要留给 RS485；调试日志只从 GPIO2 的 Serial1 TX 输出。
接线安全：电表侧必须使用隔离 RS485 模块。不要把 ESP8266、USB-TTL 或电脑直接连接到市电侧线路；不确定配电箱操作时应由电工完成。

重试与限制

  • 原文：服务端不解释 DL/T 645-2007 帧，frame_hex 按上传内容写入日志。
  • 可重试：网络错误、超时和 5xx；重试时保留原 sequence 和原始帧。
  • 不可盲重试：401、409、422 等 4xx。401 需要检查或轮换令牌，409 需要检查数据，422 需要修正请求。
  • 批次限制：每次 1～100 帧，整个 JSON 请求不超过 256 KiB；帧内容保持原始字节顺序。
安全底线：不要把真实 Token、服务器地址或兼容端口提交到 Git、写进公开截图或放在网页前端。Arduino 1.6.8 固件当前不验证服务器身份，只作为旧设备兼容入口；必须使用每设备独立、权限受限并可随时吊销的 Token。
